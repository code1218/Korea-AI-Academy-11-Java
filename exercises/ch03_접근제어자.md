## 1. 개념 확인

### 문제 1-1 ⭐
접근 범위가 **좁은 것부터 넓은 것** 순서로 나열하세요.

`public` · `private` · (아무것도 안 붙임 = default)

<details><summary>정답 보기</summary>

`private` → `default` → `public`

| 접근 제어자 | 같은 클래스 | 같은 패키지 | 다른 패키지 |
|---|:---:|:---:|:---:|
| `private` | O | X | X |
| (default) | O | O | X |
| `public` | O | O | O |

> `protected`는 상속을 배운 뒤에 다시 다룹니다.
</details>

### 문제 1-2 ⭐
Getter와 Setter의 역할을 각각 한 줄로 설명하고, `private String name;`에 대한 Getter/Setter의 이름을 쓰세요.

<details><summary>정답 보기</summary>

- Getter: private 필드의 값을 **읽어서 돌려주는** 메서드 → `getName()`
- Setter: private 필드에 값을 **넣어 주는** 메서드 → `setName(String name)`
- 이름 규칙: `get` / `set` + 필드 이름 첫 글자 대문자
</details>

## 2. 오류 찾기

### 문제 2-1 ⭐
`AccessMain`의 `run1()`에서 `s2.name = "김준이";`를 주석 해제하면 컴파일 에러가 납니다. 이유와 해결 방법 두 가지를 쓰세요.

<details><summary>정답 보기</summary>

`선생` 클래스의 `name`이 `private`이라서 **선생 클래스 바깥**(AccessMain)에서는 직접 접근할 수 없습니다.
해결: 선생 클래스가 열어 둔 메서드를 통해 접근합니다.
1. `s2.이름설정하기("김준이");`
2. `s2.setName("김준이");`
</details>

### 문제 2-2 ⭐⭐⭐ 이상한 점 찾기
`AccessMain`의 `static class 학생`도 `age`가 `private`인데, `main`에서 `s1.age = 33;`이 **에러 없이 실행**됩니다. 왜 그럴까요?

<details><summary>정답 보기</summary>

`private`은 "**같은 최상위 클래스 `{ }` 안**에서만 접근 가능"이라는 뜻입니다.
`학생`은 `AccessMain` **안에 선언된 클래스**(중첩 클래스)이므로 `AccessMain`의 main에서도 private 멤버에 접근할 수 있습니다.
반면 `선생`은 `AccessMain` **바깥**에 따로 선언된 클래스라서 접근할 수 없습니다.
</details>

### 문제 2-3 ⭐⭐ 패키지와 접근 제어
현재 패키지 구조는 다음과 같습니다.

```
com.korai.study.ch03.access
 ├─ AccessMain.java   (선생 클래스 포함)
 ├─ User.java
 ├─ entity/Role.java
 └─ service/UserService.java
```

`UserService` 안에서 아래 코드를 쓴다고 할 때, 각각 **가능(O)/불가능(X)** 을 판단하세요.

```java
User u = new User();     // ①  (User는 public class)
Role r = new Role();     // ②  (Role은 public class, import 했다고 가정)
선생 t = new 선생();      // ③  (선생은 class 앞에 아무것도 없음)
```

<details><summary>정답 보기</summary>

① O — `import com.korai.study.ch03.access.User;` 하면 사용 가능 (public)
② O — `import com.korai.study.ch03.access.entity.Role;` (public)
③ X — `선생`은 default 클래스라서 **같은 패키지(`ch03.access`)** 안에서만 사용할 수 있습니다.
`service`는 이름이 비슷해 보여도 `ch03.access.service`라는 **다른 패키지**입니다.
</details>

## 3. 코드 작성

> 실습 파일: `src/main/java/com/korai/study/practice/ch03/access/PracticeAccess.java`

### 문제 3-1 ⭐⭐ 캡슐화된 은행 계좌
`StaticBank`의 `계좌`는 누구나 `a1.잔액 = -100000;`처럼 잔액을 마음대로 바꿀 수 있는 문제가 있었습니다.
실습 파일의 `안전계좌` 클래스를 완성해 이 문제를 막으세요.

- 필드 `예금주`, `잔액`은 모두 `private`
- `getOwner()`, `getBalance()` Getter만 제공 (잔액 **Setter는 만들지 않음**)
- `입금(int 금액)` : 금액이 0 이하이면 `"입금 실패: 잘못된 금액"` 출력 후 종료
- `출금(int 금액)` : 잔액보다 많으면 `"출금 실패: 잔액 부족"` 출력 후 종료
- `boolean` 반환: 성공하면 `true`, 실패하면 `false`

**기대 출력**
```
입금 실패: 잘못된 금액
출금 실패: 잔액 부족
김준일 잔액: 8000
입금 결과: true
```

### 문제 3-2 ⭐⭐ Setter에서 값 검증하기
`점수` 클래스를 완성하세요. `private int score;`에 대해
- `setScore(int score)` : 0~100 사이가 아니면 `"잘못된 점수"`를 출력하고 값을 바꾸지 않음
- `getScore()`

**기대 출력**
```
잘못된 점수
점수: 90
```

<details><summary>정답 보기</summary>

```java
class 안전계좌 {
    private String 예금주;
    private int 잔액;

    안전계좌(String 예금주, int 잔액) {
        this.예금주 = 예금주;
        this.잔액 = 잔액;
    }

    String getOwner() {
        return 예금주;
    }

    int getBalance() {
        return 잔액;
    }

    boolean 입금(int 금액) {
        if (금액 <= 0) {
            System.out.println("입금 실패: 잘못된 금액");
            return false;
        }
        잔액 += 금액;
        return true;
    }

    boolean 출금(int 금액) {
        if (금액 > 잔액) {
            System.out.println("출금 실패: 잔액 부족");
            return false;
        }
        잔액 -= 금액;
        return true;
    }
}

class 점수 {
    private int score;

    void setScore(int score) {
        if (score < 0 || score > 100) {
            System.out.println("잘못된 점수");
            return;
        }
        this.score = score;
    }

    int getScore() {
        return score;
    }
}
```

> 💡 **캡슐화**: 데이터(필드)는 `private`으로 숨기고, 정해진 메서드로만 바꿀 수 있게 해서 **잘못된 값이 들어오는 것을 막는 것**
</details>
