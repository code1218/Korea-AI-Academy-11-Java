## 1. 개념 확인

### 문제 1 ⭐ 변수 선언의 구성
아래 코드의 각 부분이 무엇인지 빈칸을 채우세요.

```java
int num = 10;
Student jun = new Student();
```

- `int`, `Student` → ( ① )
- `num`, `jun` → ( ② )
- `=` → ( ③ ) 연산자 : 오른쪽 값을 왼쪽 변수에 넣는다
- `new Student()` → `Student` 클래스로 ( ④ )를 만든다

<details><summary>정답 보기</summary>

① 자료형(타입) ② 변수명 ③ 대입 ④ 객체(인스턴스)

`int`처럼 값을 바로 담는 것은 **기본 자료형**, `Student`처럼 클래스로 만든 것은 **참조 자료형**입니다.
</details>

### 문제 2 ⭐ O / X
맞으면 O, 틀리면 X를 쓰세요.

1. `final`이 붙은 변수는 한 번 값을 넣으면 다른 값으로 바꿀 수 없다.
2. 클래스 하나로는 객체를 하나만 만들 수 있다.
3. `Object` 타입 필드에는 숫자, 문자열, 다른 객체를 모두 넣을 수 있다.
4. `Student3<int>`처럼 제네릭에 `int`를 직접 넣을 수 있다.
5. `new Student3<String>()`은 `new Student3<>()`처럼 꺾쇠 안의 타입을 생략해서 쓸 수 있다.

<details><summary>정답 보기</summary>

1. **O**
2. **X** — 클래스는 설계도이므로 `new`를 할 때마다 새 객체가 계속 만들어집니다 (`jun`, `jun2`, `jun22`...).
3. **O** — `Object`는 모든 타입의 조상입니다.
4. **X** — 제네릭에는 기본 자료형을 쓸 수 없습니다. `int` 대신 **`Integer`**를 씁니다 (수업 코드의 `Student3<Integer>`).
5. **O** — 왼쪽에 타입이 이미 적혀 있으면 오른쪽은 `<>`(다이아몬드)로 생략할 수 있습니다.
</details>

## 2. 출력 결과 예측

### 문제 3 ⭐ 변수 재대입
실행 결과를 예측해 보세요.

```java
int a = 5;
int b = a;
a = a + 3;
b = 10;
System.out.println(a);
System.out.println(b);
```

<details><summary>정답 보기</summary>

```
8
10
```

`b = a` 시점에 **값 5가 복사**될 뿐, 이후 `a`와 `b`는 서로 영향을 주지 않습니다.
`a = a + 3`은 "현재 `a`의 값(5)에 3을 더해서 다시 `a`에 넣는다"는 뜻입니다.
</details>

### 문제 4 ⭐⭐ new 두 번 vs 참조 복사
실행 결과를 예측해 보세요.

```java
class Student {
    String name;
    int age;
}

Student s1 = new Student();
s1.name = "김준일";
s1.age = 33;

Student s2 = new Student();
s2.name = "김준일";
s2.age = 33;

Student s3 = s1;
s3.name = "박철수";
s2.age = 20;

System.out.println(s1.name + " " + s1.age);
System.out.println(s2.name + " " + s2.age);
System.out.println(s3.name + " " + s3.age);
```

<details><summary>정답 보기</summary>

```
박철수 33
김준일 20
박철수 33
```

- `s1`과 `s2`는 `new`를 **각각** 했으므로 내용이 같아도 **서로 다른 객체**입니다. `s2.age`를 바꿔도 `s1`은 그대로입니다.
- `s3 = s1`은 새 객체를 만든 것이 아니라 **같은 객체를 가리키게** 한 것입니다. 그래서 `s3.name`을 바꾸면 `s1.name`도 바뀝니다.
</details>

### 문제 5 ⭐⭐ 필드의 기본값
필드에 아무 값도 넣지 않고 출력하면 어떻게 될까요?

```java
class Student {
    String name;
    int age;
}

Student s = new Student();
System.out.println(s.name);
System.out.println(s.age);

s.age = s.age + 1;
System.out.println(s.name + "/" + s.age);
```

<details><summary>정답 보기</summary>

```
null
0
null/1
```

객체를 만들면 필드는 자동으로 **기본값**이 들어갑니다.

| 필드 타입 | 기본값 |
|---|---|
| `int` 등 숫자 | `0` |
| `boolean` | `false` |
| `String`, 클래스 등 참조 타입 | `null` (가리키는 객체 없음) |
</details>

## 3. 오류 찾기

### 문제 6 ⭐⭐ Object 필드에서 꺼내기
**컴파일 에러가 나는 줄**을 모두 고르세요.

```java
class Student2 {
    String name;
    Object age;
}

Student2 s = new Student2();
s.name = "김준이";                          // ①
s.age = "33";                              // ②
System.out.println(s.name + " " + s.age);  // ③
String a = s.age;                          // ④
Object o = s.name;                         // ⑤
System.out.println(s.age + 1);             // ⑥
```

<details><summary>정답 보기</summary>

**④, ⑥**번이 에러입니다.

- ③ `"김준이" + " "`가 이미 문자열이므로 뒤의 `Object`도 문자열로 이어 붙일 수 있습니다 → `김준이 33` 출력.
- ④ 안에 실제로 `"33"`(문자열)이 들어 있어도 **변수 타입은 `Object`**라서 `String`에 바로 담을 수 없습니다.
  → `incompatible types: Object cannot be converted to String`
- ⑤ 반대로 `String` → `Object`는 언제나 가능합니다 (조상 타입에 담기).
- ⑥ `Object`와 숫자는 `+` 계산을 할 수 없습니다.
  → `bad operand types for binary operator '+'`

> 💡 "넣을 땐 아무거나, 꺼낼 땐 불편" → 이 문제를 해결하는 것이 제네릭입니다 (문제 10에서 확인).
</details>

### 문제 7 ⭐⭐ final 과 객체
**컴파일 에러가 나는 줄**을 모두 고르세요.

```java
class Student {
    String name;
    int age;
}

final int MAX = 100;
final Student fs = new Student();
fs.name = "김준일";       // ①
fs.age = 34;             // ②
fs = new Student();      // ③
MAX = MAX + 1;           // ④
```

<details><summary>정답 보기</summary>

**③, ④**번이 에러입니다. (`cannot assign a value to final variable`)

- `final Student fs`에서 고정되는 것은 **변수 `fs`가 가리키는 객체(참조)** 입니다.
  → 다른 객체를 대입(③)하는 것은 안 되지만, 그 객체의 **필드 값을 바꾸는 것(①②)은 가능**합니다.
- ④ `MAX`는 `final int`이므로 값을 바꿀 수 없습니다.
</details>

### 문제 8 ⭐⭐ 제네릭 타입 맞추기
**컴파일 에러가 나는 줄**을 모두 고르고 이유를 설명하세요.

```java
class Student3<A> {
    String name;
    A age;
}

Student3<String> a = new Student3<String>();    // ①
Student3<Integer> b = new Student3<>();         // ②
Student3<int> c = new Student3<>();             // ③
Student3<Integer> d = new Student3<String>();   // ④
Student3<?> e = a;                              // ⑤
e = b;                                          // ⑥
```

<details><summary>정답 보기</summary>

**③, ④**번이 에러입니다.

- ③ 제네릭에는 기본 자료형(`int`)을 쓸 수 없습니다 → `Integer` 사용.
- ④ `Student3<Integer>`와 `Student3<String>`은 **서로 다른 타입**입니다. 꺾쇠 안의 타입이 같아야 합니다.
- ⑤⑥ 와일드카드 `<?>` 변수는 `Student3<String>`, `Student3<Integer>` 등 **어떤 타입의 Student3든** 담을 수 있습니다.
</details>

### 문제 9 ⭐ 반려동물 클래스
`main` 안에 `반려동물` 클래스를 만들고 객체 두 개를 생성하세요.

- 필드: `String 이름`, `int 나이`, `String 종류`
- 객체1: `"초코"`, `3`, `"강아지"`
- 객체2: `"나비"`, `5`, `"고양이"`
- 초코의 나이를 **1 늘린 뒤** 두 마리를 출력

**실행 결과**
```
초코(강아지) 4살
나비(고양이) 5살
```

<details><summary>정답 보기</summary>

```java
class 반려동물 {
    String 이름;
    int 나이;
    String 종류;
}

반려동물 p1 = new 반려동물();

p1.나이 = 3;
p1.종류 = "강아지";

반려동물 p2 = new 반려동물();

p2.종류 = "고양이";

System.out.println(p1.이름 + "(" + p1.종류 + ") " + p1.나이 + "살");
System.out.println(p2.이름 + "(" + p2.종류 + ") " + p2.나이 + "살");
```
</details>

### 문제 10 ⭐⭐⭐ 제네릭 사물함에 객체 넣기
제네릭의 타입 자리에는 `String`, `Integer`뿐 아니라 **직접 만든 클래스**도 넣을 수 있습니다.

1. `학생` 클래스: 필드 `String 이름`, `int 나이`
2. `사물함<T>` 클래스: 필드 `int 번호`, `T 내용물`
3. 학생 `김준일`(33살)을 만들어 `사물함<학생>`(번호 `7`)의 내용물로 넣기
4. **사물함 변수만 사용해서** 학생의 이름과 나이를 출력 (`사물함변수.내용물.이름`)
5. `사물함<?>` 변수에 위 사물함을 담고 번호를 출력

**실행 결과**
```
7번 사물함: 김준일(33살)
7번 사물함 확인 완료
```

> 🤔 생각해 보기: 만약 `내용물`의 타입이 `T`가 아니라 `Object`였다면 4번(`.내용물.이름`)이 가능했을까요?

<details><summary>정답 보기</summary>

```java
class 학생 {
    String 이름;
    int 나이;
}

class 사물함<T> {
    int 번호;
    T 내용물;
}

학생 jun = new 학생();
jun.이름 = "김준일";
jun.나이 = 33;

사물함<학생> locker = new 사물함<>();
locker.번호 = 7;
locker.내용물 = jun;

System.out.println(locker.번호 + "번 사물함: " + locker.내용물.이름 + "(" + locker.내용물.나이 + "살)");

사물함<?> any = locker;
System.out.println(any.번호 + "번 사물함 확인 완료");
```

**생각해 보기 답:** 불가능합니다. `Object` 타입에는 `이름` 필드가 없으므로 컴파일러가 `.이름`을 허용하지 않습니다.
제네릭 `사물함<학생>`은 `내용물`이 **학생 타입이라는 것을 컴파일러가 알기 때문에** 바로 `.이름`, `.나이`에 접근할 수 있습니다.
이것이 `Object` 대신 제네릭을 쓰는 이유입니다.
</details>
